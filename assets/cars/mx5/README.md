# car_mx5 — Mazda MX-5 (ND, soft top), lean game version

Game-ready import of the detail pass. Source, build scripts and review renders: `art/vehicles/mx5/` (README there).

| | |
|---|---|
| Files | `car_mx5.glb` (glTF binary, textures **embedded**: `mx5_body` 1024², `mx5_parts` 256², `mx5_glow` 128×64; PNG sources and the env map in `art/vehicles/mx5/detail/tex/`), `car_mx5.tscn` (ready-made VehicleBody3D scene, see below), `susp_follow.gd` (+ `.uid`) |
| Triangles | **1,692** total (cap 2,000), incl. wheels, struts/arms and FX quads |
| Blueprint IoU | side 0.978, top 0.993, front 0.971, rear 0.953 (gate side/top ≥ .95, front/rear ≥ .92) |
| Clearance | 9 poses (lock −30/0/+30° × bump/static/droop): all clear, tightest 4.5 mm (FL/FR, straight ahead, full bump) |
| Livery | made-up "Daybreak Yellow", black fabric soft top, made-up plates and badge, no real brands |

**Glow FX:** `MX5_FX_LampGlow` (head + tail lamp glow quads, 8 tris, counted in the total) is **hidden by default**.
Unhide it (or toggle `visible` from the light state) in Godot; it uses `mx5_glow.png` (left half warm head glow, right
half red tail glow), additive, unshaded.

Materials in the .glb are plain Principled (baked albedo): `MX5_Paint_Body`, `MX5_SoftTop` (same texture, matte),
`MX5_Glass`, `MX5_Under`, `MX5_Lamp`, `MX5_Wheel`, `MX5_FX_Glow`. The faked shine is the vehicle shader in
`design/art/art_direction.md` A.8 (env map: `art/vehicles/mx5/detail/tex/mx5_env.png`). Keep the paint's spec lower
than on the white GR (detail build .26, Tokyo scene .15): on this yellow a strong key highlight shows the rear-fender
facets.

## Rig (Godot VehicleBody3D / VehicleWheel3D)
```
MX5-vehicle                 root, ground, mid-wheelbase                       -> VehicleBody3D "MX5" (import hint)
 ├─ MX5_Body                ONE mesh (incl. headlamp lenses, mirrors, twin exhaust, liners, closed soft top), origin = COM estimate
 ├─ MX5_FX_LampGlow         head + tail glow quads (FX, off by default)
 ├─ Hub_FL-wheel …          empty at the static hub                            -> VehicleWheel3D "Hub_XX" (import hint)
 │   └─ Steer_FL / FR       front: rotates about local Y (vertical through the hub), ±30°
 │       └─ MX5_Wheel_FL    10-sided, origin = hub, spins about the axle
 └─ Susp_FL …               empty at the static hub: follows hub position + steer only, never spin
     └─ MX5_Susp_FL         strut + lower arm (16 tris)
```
| | front | rear |
|---|---|---|
| hub (glTF x, y, z) | ±.746, .308, +1.157 | ±.746, .308, −1.157 |
| tyre radius / width | .308 / .205 (205/45R17) | same |
| travel (clearance-tested) | +35 mm bump / −50 mm droop | +35 mm bump / −50 mm droop |
| steer lock | ±30° | – |

* Ride height: ground at y 0. The body origin (COM estimate) is 0.45 m up, at mid-wheelbase (ND is about 50:50).
* Bump is 35 mm, not the 45–50 mm default: the drawn arch is only about 4.6 cm above the tyre (A.2.7).

## Godot 4 setup
The .glb uses Godot axes: +Y up, **+Z forward, +X = car left**, ground at y 0. No node carries a rotation or scale.
The `-vehicle` / `-wheel` name suffixes are Godot import hints, so the import already gives a VehicleBody3D `MX5`
with four VehicleWheel3D `Hub_XX`.

**Option A — use `car_mx5.tscn`** (inherited scene of the .glb). It sets: mass 1,060 kg; custom centre of mass at
the `MX5_Body` origin; a body collision box (1.70 × 0.80 × 3.85 m, bottom 0.30 m above the ground); on each wheel
radius .308, `suspension_travel` .085, rest length .15, stiffness 80, damping 1.6 / 2.2, friction slip 3.0, steering
on FL/FR, **traction on the rear pair only (RWD)**; wheels and `Susp_XX` raised by 0.0985 m so the body settles at
the design ride height (same rest/stiffness/lift as the WRX and GR rigs); `susp_follow.gd` on each `Susp_XX` (`wheel` =
matching hub, `steers` on the front pair); `MX5_FX_LampGlow` hidden. Generated by `art/vehicles/mx5/godot/make_tscn.py`.

**Option B — set it up by hand** as for the other cars:
1. Import `car_mx5.glb`. `MX5` is a VehicleBody3D; set `center_of_mass_mode = Custom` and use the `MX5_Body`
   position as `center_of_mass`.
2. On each `Hub_XX` (VehicleWheel3D) keep the transform and set `wheel_radius`, `suspension_travel` and
   `use_as_steering` (front) / `use_as_traction` (rear) as in the table. VehicleWheel3D moves, steers **and spins**
   its children, so `Steer_XX` → `MX5_Wheel_XX` stay under it.
3. Attach `susp_follow.gd` to each `Susp_XX` (a sibling of the wheels), set `wheel` to the matching wheel and
   `steers = true` on FL/FR.
4. Steering: keep `VehicleBody3D.steering` within ±0.524 rad (±30°); the wells were clearance-tested only to that lock.

**Verified** in Godot 4.6.3 (Compatibility / OpenGL3 on llvmpipe, in a scratch copy of the project): the .glb imports,
the scene loads with no script errors, the car settles at body y 0.000, drives (rear-wheel drive) and steers (22.9°
at steering .40), and the struts follow travel and steer. Screenshot sheet:
`art/vehicles/mx5/detail/renders/mx5_detail_godot46_800.jpg`. As with the WRX and GR rigs, Godot's raycast wheels sit
about 2 cm lower than the static hub at rest (wheel y ≈ .287 vs .308). The scratch import used
`filesystem/import/blender/enabled=false`, as for the GR.
